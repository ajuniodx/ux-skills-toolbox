# Product Evolution

## 1. Frame the initiative
Answer in writing before any design work: **Why** (problem + evidence), **Who** (segment), **What success looks like** (one primary metric, guardrails), **What we don't know** (riskiest assumptions), **Scope** (in/out).

## 2. Design rationale
Every proposal ships with: problem → evidence → options considered → chosen option → trade-offs → how we'll measure. Keeps reviews about reasoning, not taste.

## 3. From problems to opportunities
- Map problems from support tickets, analytics, research and sales; cluster by user outcome.
- Phrase each as an opportunity ("Users need a way to…"), never as a feature.
- Use an **opportunity solution tree**: desired outcome → opportunities → solutions → experiments. Compare several solutions per opportunity.

## 4. Test cheaply
- **Fake door**: expose an entry point for an unbuilt feature, measure clicks, show an honest "coming soon" message. Define the success threshold beforehand; keep exposure small and ethical.
- Other options: concierge, Wizard of Oz, prototype test, painted door in email.

## 5. Ideation: lightning demos
Each participant brings 2–3 inspiring products (any industry), demos each in ≤3 min; capture the reusable ideas as sketches/notes. Timebox to 45–60 min.

## 6. Design QA before release
- Review in a staging build on real devices against specs: layout, states (empty, loading, error), copy, accessibility, responsive breakpoints, analytics events.
- Log issues with severity (blocker / major / minor) and screenshots; blockers stop release.

## 7. Team rituals
- **Daily**: 15 min, focused on progress toward the sprint goal and blockers.
- **Retrospective**: set the stage → gather data → generate insights → decide 1–3 actions with owners → close. Review last retro's actions first.

## 8. Growth design
Design for the funnel: acquisition → activation (time to first value) → retention → referral → revenue. Find the biggest drop-off, form a hypothesis, test, iterate. Onboarding should get users to the "aha" moment with the fewest steps.

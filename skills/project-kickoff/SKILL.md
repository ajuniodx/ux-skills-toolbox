# Project Kickoff

Goal: reach the first validated delivery in 2–4 weeks with shared understanding of the problem, not just a screen.

## 1. Set up before the first meeting
- One workspace per project with: milestones calendar, task board (Backlog → Doing → Review → Done), decision log, and a deliverables page.
- Write down known constraints first: deadline, budget, stakeholders, who approves.

## 2. Kickoff / briefing
Always hold a live briefing, even if you received written requirements. Leave with answers to:
- **Problem**: what is broken, for whom, since when, and how do we know?
- **Context**: in which situation does the problem occur and what does it cost the business?
- **Success**: which metric or observable behavior changes if we succeed?
- **Requirements & constraints**: separate must-haves from assumptions; show how each requirement affects time and cost.
- **Existing hypothesis**: what does the stakeholder already believe the solution is? Record it as a hypothesis, not a decision.
Output: a one-page brief everyone signs off on. If the product already exists, a Lean UX Canvas works well.

## 3. Diagnose before designing
- **Heuristic review**: walk the main flows against Nielsen's 10 heuristics; rate each issue by severity (0–4) and frequency, attach a screenshot and a fix suggestion.
- **Competitor analysis**: include indirect competitors and substitutes. For each, note what works, what fails, and what is transferable.
- **Accessibility baseline**: check contrast, keyboard/focus order, labels and target sizes against WCAG 2.2 AA. Treat accessibility as a requirement from day one.

## 4. Who we design for
- Proto-personas from what the team knows, explicitly marked as assumptions; replace with research-backed personas as soon as possible.
- Prefer goals, context and frustrations over demographics.

## 5. Visual direction
- A moodboard (type, color, imagery, UI references) aligned with stakeholders **before** high-fidelity screens. References can come from other industries.

## 6. Validate and deliver
- Test the riskiest flow with 5 users (moderated usability test, think-aloud, task success + notes).
- Deliverables can be screens, a report, a prototype or a decision memo — agree on the format in the brief.

## Checklist
- [ ] Brief approved, success metric defined
- [ ] Heuristic + competitor + accessibility findings documented
- [ ] Personas labeled as assumption or evidence
- [ ] Riskiest flow tested with users before final handoff
